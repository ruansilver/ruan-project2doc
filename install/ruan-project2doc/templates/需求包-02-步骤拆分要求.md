# 步骤拆分要求

> 给 ruan-dev-skills 规划 S 步骤用。单元的完整定义在 `规则/编排与交接物.md` 第 2、3 节；本文件是它的执行要点。S-ID 的编号、拆分和废弃按 dev-skills 开发协议执行。

## 一、步骤序列

1. **S001 环境确认**（dev-skills 固定）：见 `00-任务说明.md` 第三节。
2. **每篇三个步骤**，按 `01-拆分方案.md` 的篇号和衔接顺序：U-取证 NN → U-成文 NN → U-校对 NN。篇与篇之间串行，让后一篇能读到前一篇的终点摘要。
3. **U-收束**（最后一个步骤）。

只详拆近期步骤；远端步骤保留粗目标即可。

## 二、每类单元的要点

| 单元 | 读什么 | 明确不读 | 输出 | 完成判据（步骤的验证方式） |
|---|---|---|---|---|
| U-取证 NN | 本篇对应的 map 模块（只读相关节点与未决）；本篇入口到终点之间的源码；`_术语表.md`；`规则/project-map借鉴.md`、`规则/问题清单.md` 附录 B、`规则/概念定义.md` | 其他篇的源码与 map 模块 | `_工作区/_事实/NN.md`（从 `模板/_事实.md` 复制）；`_问题台账.md` 登记；`_术语表.md` 只追加 | 每条事实有来源与核对状态；关键数据四格填满；覆盖矩阵每行有去向；B1、B2 自查逐 ID 落盘；无未处理的 P0、P1；拆篇信号未命中（命中就回 U-拆分，交调整） |
| U-成文 NN | `_事实/NN.md`、`_术语表.md`、`_衔接约定.md`；`规则/写作规范.md`、`规则/约束取舍表.md`、`模板/单篇笔记.md` | 源码（需要新事实时退回 U-取证）、其他篇正文 | `NN-<标题>.md` | 符合单篇模板；正文没有事实摘要以外的事实；附录 A 快速自查完成；`工具/project2doc.py lint` 与 `consistency` 已运行并处理 |
| U-校对 NN | 该篇；相邻篇 `_事实/` 的首尾；`规则/校对协议.md`、`规则/写作规范.md`、`规则/约束取舍表.md`、`规则/问题清单.md` 附录 A | 源码、其他篇全文 | 修改后的该篇；`_工作区/_校对记录/NN.md`（从 `模板/_校对记录.md` 复制） | 两轮按 ID 落盘；校对停止条件满足（K17）；没有改动事实、数字、结论强度（需要的已列入“退回准确性链路”） |
| U-收束 | 各篇的标题目录与首尾；`_术语表.md`、`_衔接约定.md`、全部 `_事实/` 的“未确认”节、`_问题台账.md`；`规则/自检清单.md` 第 2 节 | 各篇正文全文 | 00 定稿（回填“一句话结论”与术语表）；`99-复核说明.md`；修改提示词文档（`工具/project2doc.py render-revise`，再填项目口径区） | `规则/自检清单.md` 第 2 节全部通过；`consistency` 无失败项 |

**每个步骤文件都要写明**：本步读需求包里的哪几份（文件名 + 章节）、明确不读什么、输出到哪里、完成判据对应的检查 ID。

## 三、用户验收节点

- 每篇的**校对步骤**完成后，《当前状态》的“下一动作”写成“等待用户确认第 NN 篇”。用户确认后再开下一个会话推进下一篇。
- 用户对某篇提出修改时，按 `规则/修改协议.md` 处理。

## 四、预算与拆篇

- 单元读入的原始材料加产出，不超过上下文的一半（默认值，可后改）。
- U-取证超预算或命中拆篇信号（`规则/概念定义.md` K18）时，结束当前步骤，作为需求调整把这一篇拆成两篇：拆的是篇，不是段落。
- 发现退化信号（`规则/编排与交接物.md` 第 6 节）时，优先结束当前步骤、换会话。

## 五、提交

每个步骤验证通过后在笔记仓提交，提交信息带版本号和 S-ID；提交 hash 回写进度。只提交笔记仓，从不推送。
