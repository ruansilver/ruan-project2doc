# 笔记生成任务说明

> 本文件是 ruan-project2doc 交给 ruan-dev-skills 的需求包入口，归档为 P001。

## 一、目标

为 `<仓库名>` 生成一套中文链路笔记：`00-总览与主线地图.md`、`01..NN` 链路篇、`99-复核说明.md`，以及修改提示词文档 `修改已有笔记-<仓库名>.md`。每篇以一条主流程为主干，忠于当前源码，读者能顺着读下去。

目标读者：有一般软件工程基础、但不熟悉本项目的开发者（`规则/概念定义.md` K13）。

## 二、被分析的源码仓（只读）

| 项 | 值 |
|---|---|
| 路径 | <绝对路径；多仓时每个仓一行> |
| 分析基准提交 | <完整提交号> |
| project-map | <路径与状态；或“无”> |

**源码仓与 project-map 只读**：任何步骤都不改它们，不在其中运行写入命令。

## 三、这里的“代码仓”是笔记仓

- dev-skills 眼中的代码仓是 `<工程>/笔记/`（会话工作目录），不是被分析的源码仓。
- 步骤完成的证据是**笔记仓**的提交 hash。只提交笔记仓，从不推送。
- **S001“环境确认与原始基线”**：笔记仓没有构建和测试可跑。S001 只确认笔记仓的 Git 状态、记录基线 hash，并确认源码仓 HEAD 与上面的分析基准一致、`工具/project2doc.py deps` 通过，照常完成。

## 四、产出位置

| 产出 | 位置 |
|---|---|
| 笔记正文 | `<工程>/笔记/` |
| 交接物 | `<工程>/笔记/_工作区/`（随笔记仓提交，读者不用看） |
| 进度与接力 | `<工程>/docs/AI dev docs/<版本号>/`（dev-skills 管理） |

## 五、规则在哪里

本需求包的 `规则/` 是 ruan-project2doc 的 references 副本，`模板/` 是 templates 副本，`工具/project2doc.py` 是辅助脚本。步骤文件按“P001 + 归档内相对文件 + 标题”引用具体规则；规则之间冲突时按 `规则/约束取舍表.md`。

## 六、源码仓变化时

每个 U-取证步骤开工时，比较源码仓 HEAD 与分析基准（`git -C <源码仓> rev-parse HEAD`）。变化了就列出受影响的篇目（看各篇 `_事实/NN.md` 引用的路径），作为“需求调整”新增重新取证的 S 步骤，**不在当前步骤里顺手处理**（`规则/编排与交接物.md` 第 5 节）。

## 七、每步额外报告

每个步骤结束时，除 dev-skills 开发协议要求的回写外，再报告一行：本步产物、未确认项数量。
