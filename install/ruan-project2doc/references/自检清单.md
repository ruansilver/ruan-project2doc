# 自检与验收清单

**何时读本文件**：每个单元结束时。

清单本身在 `问题清单.md`，这里只规定**谁在什么时候执行哪一组、结果写到哪里**。执行结果必须落到文件里，逐个 ID 写明“命中位置 / 无”；只写“已检查”视为没有执行。

## 1. 单篇（每篇成文后、每次修改后）

| 时机 | 执行 | 结果写到 |
|---|---|---|
| U-取证结束 | 附录 B 的 B1、B2（F01–F20），以及关键步骤覆盖矩阵；拆篇信号（K18） | `_事实/NN.md` 末尾的“自查结果”；命中项登记 `_问题台账.md` |
| U-成文结束 | 附录 A 全组快速自查；再核对正文每个事实都能在 `_事实/NN.md` 找到条目，数字与术语和 `_术语表.md` 一致；运行 `project2doc.py lint` 和 `consistency` | 步骤文件的验证记录 |
| U-校对 | 附录 A 逐条（两轮分工见 `校对协议.md`）；最后用“说人话”类 Skill 做一次表达自检（本机可用时） | `_校对记录/NN.md` |
| 用户修改 | 附录 D（M01–M08），加上受影响段落的附录 A 相关条目 | 修改提示词文档的变更记录 |

**四条最低门槛**（任何时候都不能放过）：

1. 每个一级节读完，能用一两句话说清它在做什么（R20）；
2. 主线段落删掉所有反引号里的源码名，仍能读懂（R06）；
3. 每个主流程步骤写了“防的是什么”（R15）；
4. 同级步骤超过约 15 步或跨过两个可观测终点，就拆篇（K18）。

### U-取证结束时的额外检查

- [ ] 每条事实都有来源（`project-map借鉴.md` 第 6 节的三种之一）和核对状态；
- [ ] 每个关键数据（K06）都填满“来源 → 传递 → 使用或校验 → 生命周期”四格；
- [ ] 关键步骤覆盖矩阵每行是“已覆盖”，或写明不覆盖的理由和去向；
- [ ] 借鉴 map 的事实按信任分级处理，必须核对的都核对了；抽查不一致的模块已整体改为必须核对；
- [ ] 与 map 不一致的地方已记下，留给 99；
- [ ] B1、B2 组无未处理的 P0、P1（P0、P1 在本步骤内处理或退回；P2 可留给校对）；
- [ ] 源码仓 HEAD 与 `_勘察结果.md` 的基准一致；不一致按 `编排与交接物.md` 第 5 节处理。

### U-成文结束时的额外检查

- [ ] 符合 `templates/单篇笔记.md` 的结构；
- [ ] 篇首的“覆盖 / 不覆盖”和篇尾的接口，与 `_拆分方案.md`、`_衔接约定.md` 用的是同一个名字；
- [ ] 正文没有事实摘要里没有的事实；
- [ ] 推断、未确认都打了短标签，没有被概括成确定结论。

## 2. 全局（U-收束）

- [ ] 00 的篇目清单与实际文件一致；每对相邻篇的终点和起点是同一事物；
- [ ] 术语在各篇一致，00 的术语表由 `_术语表.md` 生成；
- [ ] 00 的“一句话结论”只引用已落盘的事实条目，没有提高结论强度；
- [ ] 99 汇总了各篇事实摘要中的全部未确认项，以及与文档、project-map 的冲突；
- [ ] 修改提示词文档已生成，项目口径区已填写；
- [ ] 附录 B 的 B3 组（F30 反向缺口、F31 横切专题、F32 跨篇一致）通过；
- [ ] `_问题台账.md` 无 open 项（needs_user_decision 的项已列进 99 的“要用户决策的点”）；
- [ ] `project2doc.py consistency --notes <笔记>` 无失败项，警告项逐条处理或写明保留理由。

## 3. 验收

一篇笔记合格 = 第 1 节各时机的检查都已执行并落盘，附录 B 无未处理的 P0/P1，附录 A 命中项已处理或在校对记录中写明保留理由。

用户验收节点：拆分方案确认一次；之后每篇的取证、成文、校对三个步骤都完成后确认一次。
