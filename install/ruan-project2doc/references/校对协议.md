# 校对协议

**何时读本文件**：U-校对；用户修改中只涉及表达或结构的要求。

## 1. 定位

校对是独立于撰写的环节。输入只有：该篇全文、相邻篇事实摘要的首尾（检查接口）、`写作规范.md`、`约束取舍表.md`、`问题清单.md`。**不读整个仓库，不读源码**。

## 2. 校对维度与两轮分工

下面七个维度是总纲，**实际执行按 `问题清单.md` 附录 A 的 R 编号逐条进行**，结果写入 `_校对记录/NN.md`。

1. **主干是否清晰**：只看标题能否还原流程；每个一级节能否用一两句话复述（R20、R34）。
2. **就地展开后是否回到主线**：补充块是否紧跟所补充的步骤；下一句是否回到主流程（R21、R24、K09、K10）。
3. **是否由浅入深**：有没有一句话主线和全景图；异常是否下沉到补充块，没有和正常流程同级（R25、K11）。
4. **过渡是否自然**：有没有模板化转场；相邻两步之间是否“一句推一句”（R40、R41、R42）。
5. **重点是否点明**：关键结论是否用加粗或提示块，而不是靠标题或换句式重复（R27、K07）。
6. **代码名密度**：主线段落去掉源码名后是否仍能看懂（R06）。
7. **动机**：每个主流程步骤是否写了“防的是什么”（R15、K08）。

**两轮分工**（默认值，可后改）：

| 轮次 | 查什么 | 理由 |
|---|---|---|
| 第 1 轮 | 结构与层级：A2（R20–R29）、A3（R30–R38）、A4（R40–R42）、A5（R50–R52） | 结构调整会改写句子，先调结构再抠句子可以避免返工 |
| 第 2 轮 | 句子与术语：A1（R01–R17） | — |

每轮先运行一次候选扫描，作为线索（不能代替逐条判断）：

```bash
python "<脚本路径>/project2doc.py" lint --file "笔记/NN-标题.md" [--words <项目追加的 AI 味词> ...]
```

## 3. 记录格式

`_校对记录/NN.md` 按 `templates/_校对记录.md` 填写。每轮逐个 ID 写一行：

| ID | 命中位置（节号 + 原句） | 处理 |
|---|---|---|
| R03 | 二、第 3 步：“随后写入 Outbox。” | 首次出现处补括注“（待发送事件表）” |
| R10 | 无 | — |

- **不允许只写“已检查”**，也不允许整组写“无问题”。每个 ID 都要有一行，命中写位置和原句，未命中写“无”。
- 命中项按第 4 节的权限边界处理；需要改事实的写进“退回准确性链路”表。
- 每轮末尾写轮次结论：A2–A5 组是否零命中；A1 组的命中是否都已标为“可选”（K17）。

## 4. 权限边界

| 可以改 | 不可以改 |
|---|---|
| 表达、句子顺序、段落顺序、过渡、详略、标题措辞、补充块的层级 | 事实、数字、源码依据、结论强度（已核实 / 推断 / 待核实的标记） |

**需要改事实时**，在 `_校对记录/NN.md` 的“退回准确性链路”表里记一条（位置、原句、怀疑什么、对照的事实摘要条目编号），由新的 U-取证单元处理；正文中这一句**保持原样**。理由：校对单元不读源码，在这里改事实只能凭记忆，正是准确性最容易出错的地方。例如发现正文写“重试 5 次”而事实摘要写“3 次”，校对不改成任何一个数，而是退回取证。

纯措辞改动要对照事实摘要确认含义不变；拿不准含义是否变了，就不改（C17）。

## 5. 执行者与轮数

- 由**独立会话或独立子 agent** 执行，不让作者自评。在 dev-skills 编排下，校对是单独的 S 步骤，天然在新会话里进行。理由：作者会把自己知道但没写出来的上下文自动补上，看不出悬空句和跳步。
- **最多 2 轮**。停止条件：七个维度都没有新问题；或者第二轮只剩措辞偏好（K17：A2–A5 零命中，A1 命中都标为“可选”）。
- 超过 2 轮仍有结构性问题，说明是拆分或取证的问题，退回对应单元，不继续润色。
- 收尾时如果本机有“说人话”类 Skill（例如 shuorenhua），用它做一次表达自检；它的改动同样受第 4 节约束。

## 6. 与修改流程的关系

复用同一套流程，入口不同：

- 生成期校对：输入是写作规范和取舍表；
- 用户后续修改：输入是同样的规范，加上修改提示词文档「三、用户追加区」的新要求。

两者都遵守同一个权限边界：涉及事实的要求走准确性链路（U-取证），只涉及表达的走本协议。
