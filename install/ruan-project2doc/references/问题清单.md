# 问题清单（R / F / M 编号，单一来源）

**何时读本文件**：U-取证（附录 B）、U-成文与 U-校对（附录 A）、修改时（附录 D）。步骤文件、校对记录、问题台账一律**只按 ID 引用**本清单，不要每次凭自己的理解去复述“可读性”是什么。

**用法**：

- 每条有稳定 ID、一个判定问题（检验）、反例和正例。执行时逐个 ID 写“命中位置（节号 + 原句）/ 无”。**不允许只写“已检查”**。
- 命中项按 `校对协议.md` 的权限边界处理；附录 B 的命中项登记 `_问题台账.md`。

**例句说明**：标“真实例句”的句子摘自一套真实笔记、它的修改要求和一份真实的复审问题台账，集中在同一个业务领域（上传、消息、缓存、认证）。它们**只说明问题的形态，不说明目标项目会有这些组件**。每一组另附一条“示例，非领域知识”的通用改写。运行时检查和改写，都以目标项目自己的句子为准。标“示意”的是按原文描述改写的。

| F12 | 执行顺序写错，或者前后矛盾 | 关于顺序的说法，有没有逐行回到源码核对？同一个流程在不同篇、不同图里的顺序一致吗？ | P0 R2-USER-004：缓存失效的先后顺序写反了；R2-AUTH-013：流程图把切面画在了参数校验之前 |
| F13 | 夸大了防护或能力的范围 | “防住了 X”这种说法，覆盖的是全部入口，还是其中一个？ | P0 R2-PARSE-001：“误称完整防目录穿越；实际只防 ZIP entry” |
| F14 | 写了代码里不存在的功能 | 对用户的承诺（响应文案、客户端提示、文档描述）能在代码里找到实现吗？ | P0 R2-USER-008：承诺会发审批邮件通知，但当前版本没有邮件发送实现 |
| F15 | 把理想中或设计中的行为写成了现状 | 这句话描述的是代码现在的行为，还是“应该怎样”？ | R2-AUTH-014：“把 401 机器码对应的理想客户端动作写成当前事实” |
| F16 | 对异常捕获或错误映射的范围描述不准 | 写“捕获了 X 异常”时，代码实际捕获的范围比 X 宽还是窄？多种不同的失败，是否被映射成了同一个错误码？ | “捕获全部唯一约束异常，却把它窄化描述为待审批唯一键竞态” |
| F17 | 版本归属写错 | 版本表里的每一项，有没有用迁移号、提交记录或上线留档核对过？ | P0 R2-AUTH-019：迁移 V20 被错归到了别的版本 |
| F18 | 用测试证明了超出测试范围的结论 | 测试实际断言了什么？结论有没有超出这些断言？ | “把前端共享规则测试扩大成防止前后端规则漂移” |
| F19 | 示例绕过了真实的执行顺序 | 这个例子在真实的入口下成立，还是只在直接调用内部函数时才成立？ | “带空格用户名的示例绕过了真实 HTTP 参数校验顺序” |
| F20 | 把没有证据的“为什么”写成了结论 | 对设计原因的解释，有代码注释、提交历史或文档作为来源吗？没有就标【推导】 | — |

示例，非领域知识（B2）：“支付成功后一定会给用户发短信”——代码里短信发送失败只记日志、不重试（F10）；“所有接口都做了幂等”——实际只有下单和支付两个接口查幂等表（F11）。

### B3　全局覆盖（U-拆分与 U-收束时执行）

| ID | 毛病 | 检验 |
|---|---|---|
| F30 | 代码里有、笔记里没有（反向缺口） | 附录 G 第二列的全部入口类型（请求入口、安全入口、消费者、生产者、扫描任务、死信清理、异步线程、定时任务……）和第三列的全部终点类型（数据库表、缓存键、对象存储中的对象、消息主题、限流资源……），以及测试主题，是否都能对应到某一篇笔记？对应不上的，是否在 00 的“不覆盖”表里写明了原因？ |
| F31 | 横切专题完全没写 | U-拆分时先列出横切专题：测试体系、数据库迁移、多环境配置、安全与权限、可观测性、部署、缓存、限流，再加上项目特有的专题。每一项要么分到某一篇，要么在 00 里写明不覆盖的原因 |
| F32 | 同一事实在不同篇里说法不一致 | 同一个数字、状态名、执行顺序，在各篇里写得一样吗？ |

真实例子：一套 7 篇的笔记里，测试体系、数据库迁移、多环境配置三个专题都是“零覆盖”，用户注册审批链路“散落碎片”（F31）。

**优先级**：

- P0：事实错误，会误导读者；
- P1：关键链路缺失，或者范围、强度失真；
- P2：表达问题或局部口径问题。

P0 和 P1 必须在本步骤内处理，或者退回取证；P2 可以留给校对环节。

## 附录 E　问题清单的维护（防止跑偏）

- **运行时只引用 ID**：步骤文件、校对记录、问题台账都用 R、F、M 编号指代问题。
- **项目级扩展**：用户在修改提示词文档里追加的要求，如果同一类出现了第二次，AI 就在项目口径区的“项目特有问题”表里登记一个项目级 ID（如 `P-R01`），格式与附录 A 相同：毛病、检验、反例与正例、出处。
- **回流到 Skill**：项目级条目只在本项目内生效。多个项目反复出现同一个问题时，由用户决定是否把它并入本 Skill 的 references。AI 不在运行时修改 Skill 本身。
