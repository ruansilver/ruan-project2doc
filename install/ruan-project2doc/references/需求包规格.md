# 需求包规格与笔记工程目录

首次建工程、确认规划后交接，以及修改时准备材料，读本文件。各单元细则见《生产流程与交接物》。

## 1. 目录与责任

```text
<仓库名>-笔记工程/
  笔记/                         独立 Git 根
    00-系统总览与阅读路线.md
    01-标题.md ... NN-标题.md    链路篇与机制专题篇
    99-复核说明.md
    修改已有笔记-<仓库名>.md
    _工作区/
      _勘察结果.md
      _规划方案.md
      _术语表.md
      _衔接约定.md
      _问题台账.md
      _研读/NN.md
      _审读记录/NN.md
  需求包/
    00-任务说明.md
    01-规划方案.md
    02-步骤拆分要求.md
    规则/                       references 副本
    模板/                       templates 副本
    工具/project2doc.py
  docs/AI dev docs/              dev-skills 管理的独立资料仓
    笔记v1/                     版本目录
```

工程根目录是普通目录，不执行 `git init`。笔记仓作为 dev-skills 所称的代码仓，资料仓由它单独创建，需求源位于资料仓之外。这样所有写入都留在输出工程，不进入被分析仓库或 project-map。

工程目录名、笔记文件名和 `笔记v1` 都是默认值、可后改。只提交笔记仓，不推送；本 Skill 不代管资料仓的 Git 操作。

## 2. scaffold 与模板

```bash
python "<SKILL>/scripts/project2doc.py" scaffold --project "<工程>" --repo-name "<仓库名>"
```

scaffold 初始化笔记仓，放入 00、99 及 `_工作区/` 的五份共用交接物，创建空的 `_研读/`、`_审读记录/` 目录；按篇文件在相应单元从模板复制。需求包复制本版本规则、模板和工具，并放入任务说明与步骤拆分要求模板。已有文件不覆盖。

空的研读和审读目录位于笔记仓，不进入需求包。需求包归档前不得有空目录或符号链接，不得放在资料仓内；敏感信息不放进去，因为 dev-skills 会原样归档。

## 3. 确认后的需求包

| 文件 | 应写内容 |
|---|---|
| `00-任务说明.md` | 学习目标、只读源码仓与基准、输出位置、用户重点；明确代码仓是笔记仓，初始步骤只记基线；说明源码变化后的重新研读安排 |
| `01-规划方案.md` | 用户确认后的 `_规划方案.md` 完整副本，包括机制级别、主讲篇、两类篇目、阅读顺序、学习目标、追问和入口去向 |
| `02-步骤拆分要求.md` | 每篇研读、成文、审读三个新会话步骤；输入、输出、完成判据、审读后等待用户确认；两类篇都按阅读顺序推进 |
| `规则/` | 定位与标杆、讲解规范、表达规范、篇目规划、生产流程与交接物、质量门、修改协议、需求包规格、project-map 借鉴 |
| `模板/` | 两类篇、00、99、修改提示词、所有交接物、任务说明与步骤拆分要求 |
| `工具/project2doc.py` | 可在需求包内独立使用的辅助脚本 |

步骤文件引用“P-ID + 归档内相对文件 + 标题”，例如引用实际归档中的 `规则/质量门.md` 的 G1。以 dev-skills 返回的归档结构为准，不能猜目录多一层或少一层。步骤中明确本次要读的规则，不要求每次通读全部副本。

写作规则放在需求包里。dev-skills 的固定协议和接力提示词按它自身规范管理，不把本 Skill 规则塞进或改写这些固定文件。

## 4. 初始化编排

前提是规划已确认，三份需求文件已填好，笔记仓已有骨架提交。工作目录切到 `<工程>/笔记/`，加载已安装的 ruan-dev-skills，以初始化模式提供：

- 需求材料：`<工程>/需求包/`；
- 版本目录：`<工程>/docs/AI dev docs/笔记v1/`。

由它初始化资料仓、归档需求、规划步骤并准备接力，直到状态为“可接力”。每篇仍是研读、成文、审读；审读步骤的下一动作写“等待用户确认第 NN 篇”。首次调用在此结束，后续按接力提示词进入新会话。

ruan-dev-skills 是正常长任务的硬依赖，缺失则停止并说明缺什么，不自建编排替代。在 Windows 上运行它的 Python 脚本时使用 `python -X utf8`，避免中文路径和 Git 输出按系统编码解码失败；具体参数读取当前安装的 dev-skills 说明，不凭旧调用拼写。

## 5. 修改与基准变化

修改按《修改协议》另建需求材料目录，交给 dev-skills 调整模式，保留旧归档。源码基准变化时先列出变化路径与受影响篇目，再新增重新研读步骤；既不能悄悄沿用旧事实，也不能在收束步骤大改机制讲解。
