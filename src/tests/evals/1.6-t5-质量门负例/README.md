# 质量门负例：三份合成短文

这是通用“会议室预订”场景的合成夹具，用于验证 1.6 的质量门能拒绝三类结构问题。事实基准是 `source/booking.py`（只读）；它是合成代码，不对应任何真实项目，不能据此声称真实系统具有这些行为。

| 夹具 | 植入的问题 | 应被哪里拒绝 |
|---|---|---|
| `负例1-独立操作排进主链.md` | 机制题都答得出，但各节首段连不成线；取消、签到、定时释放与提交、审批排成“第一步……第六步”；全貌只有一条实线链 | G1 的阶段 A 骨架复述 |
| `负例2-图后文字与图形不符.md` | 图后文字说“菱形是条件分支，虚线是失败出口”，图里没有判断节点和虚线边 | `lint` 的 G3-图例不符；G3 第 9 项 |
| `负例3-结论只在补充块.md` | 主干与小结写“提交后立即生效”，默认配置下要等管理员审批这条事实只出现在补充块 | G3 第 8 项（并且折叠检验不通过） |

## 执行步骤

1. **负例 1**：对正文运行 `skeleton`，把骨架视图交给一位没有本次上下文的独立读者，按阶段 A 的四项要求复述并保存原答；再给正文全文做阶段 B；最后给 `追问.md` 做阶段 C。核对者读 `判定要点.md` 和 `source/booking.py` 判定。按规则修复后冻结新版本，换一位新的独立读者重跑阶段 A。
2. **负例 2**：运行 `lint`，确认报出 G3-图例不符；核对者按 G3 第 9 项判定。修复方式必须是改图或删掉与图不符的说明——只在图后再补一段文字不算修复。修复后 `lint` 不再命中。
3. **负例 3**：核对者按 G3 第 8 项与折叠检验判定。修复后让独立读者只看骨架视图复述，应能说出默认配置下提交之后停在哪里。

独立读者只接触规定的输入（骨架视图 → 正文 → 题面），不得读 `判定要点.md`、`source/` 或其他夹具。原答、判定、修改位置和复验结果都要保留；首次结果与复验结果分开记录。

## 已知局限

合成源码没有实现冲突检查（`find_conflict` 由调用方注入），所以“哪些状态的预订算占用时段”在夹具里无法确认。实测中，首轮和复验的独立读者都把它列为最重的初读障碍——“审批时把自己排除在外”与“提交时已有重叠就不保存”放在一起，读者举不出“提交时没冲突、审批时有冲突”的具体过程。合格的修复稿应如实写明这一点无法确认，而不是自行补一个范围。它不属于三处植入问题，判定负例与复验时不计入。

本夹具写成时只核对了文本与 `source/booking.py` 的事实口径；独立 Agent 的行为评测须按上述步骤另行执行，记录归入当次的验收材料，不把一次性答题日志提交到夹具目录。
