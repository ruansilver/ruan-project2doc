# 勘察结果

> 由 U-勘察填写；源码基准变化时更新。可用 `project2doc.py survey --repo <仓库> [--map <map>] --json` 的输出填写。

## 源码

| 字段 | 值 |
|---|---|
| 仓库路径 | <绝对路径；多仓时每个仓一行> |
| 分析版本或分支 | <默认当前 HEAD> |
| 源码基准提交 | <完整提交号> |
| 工作区是否干净 | <是 / 否：未提交的路径> |
| 勘察日期 | <YYYY-MM-DD> |

## 技术栈与规模

| 字段 | 值 |
|---|---|
| 项目类型（附录 G） | <HTTP 服务端 / 消息驱动 / 前端 / 移动端 / 数据管道 / 命令行 / 库 / 多端> |
| 主要语言与文件数 | <语言：文件数> |
| 构建文件 | <路径> |
| 子项目或模块 | <目录：用途> |
| 是否有执行链路 | <是 / 否：否则说明不适用并停止> |

## project-map

| 字段 | 值 |
|---|---|
| 是否存在 | <是：路径 / 否：走自带路径> |
| map 源码基准 | <提交号；多仓时每个仓一行> |
| 与当前 HEAD | <一致 / 落后 N 个提交、M 个文件有变化> |
| 变化路径 | <diff --stat 涉及的路径，或“无”> |
| STATE 九项统计 | 梳理中 <n>、待验收 <n>、本层完成 <n>、已证叶子 <n>、待办 <n>、阻塞 <n>、入口 <n>、汇点 <n>、覆盖记录 <n> |
| 模块状态 | <模块文件：状态 / 限制> |
| 发现暂时收敛 / 整体完成 | <是或否 / 是或否> |
| check.py | <退出码 0 / 1 / 2；失败项；或“未执行：原因”> |
| 信任结论 | <哪些模块整体按“必须核对”对待，原因> |
