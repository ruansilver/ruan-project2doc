# 质量门

六道门检查同一个结果：笔记准确，读者能讲清整体、流程和机制。成文自查 G2、G3、G5；审读按《生产流程与交接物》的三轮执行 G1–G6。成文自查记在理解稿末尾，审读结论集中记在 `_工作区/_审读记录/NN.md`。各门全部通过后才进入该篇的用户确认。

## G1：读者能否讲清整体并回答追问

| 证据 | 通过条件 |
|---|---|
| 阶段 A 骨架复述 | 全貌、各章职责和“哪些不是同一次执行”没有重要错误。不把独立触发的操作说成必经步骤，不把跨参与方的多次往返说成一次请求，主要阶段与产物正确 |
| 阶段 B 通读复述 | 完整复述没有重要错误：阶段顺序、对象关系、执行边界、关键结果正确 |
| 初读障碍清单 | 逐条处理：修改正文，或写明保留理由；同一类障碍成批处理 |
| 阶段 C 逐题作答 | 必答题（整体复述题、子流程复述题、用户指定的问题）与核心机制的题全部答得出且正确；其余题答得出且正确的比例不低于 80%（默认值，可后改） |

**骨架复述或通读复述不通过时，机制题全部答对也不能通过。** 80% 的比例不能抵消错误的主线、错误的状态关系或未经核实的保证。追问清单的分层与出题纪律见《篇目规划》；读者与正文版本的设置、三轮的次序见《生产流程与交接物》。

记录：正文冻结版本、读者标识与输入范围、三个阶段的原答、逐题判定与正文出处、核对依据、缺口与复验。

## G2：机制讲解完整

核心机制在主讲篇逐一对照七问；支撑机制，以及链路篇用到的别篇主讲的核心机制，对照①③⑤。逐个机制记录正文位置。内容都在但零散得拼不成一个机制，也算不通过。确实不适用的写原因；没查清退回研读。七问内容见《讲解规范》。

## G3：组织与流程

**组织检查**，逐项记录结论和依据：

1. 实际组织方式与讲述方案一致；各类内容的位置符合《讲解规范》的内容类别表（独立操作、旁路、横切机制没有被排成主链步骤）。
2. 标题职责与目录检验：每一级标题说明该部分在流程或机制中的作用、概括其全部内容；只读一至三级标题能还原执行过程或主题结构；同级同依据。
3. 多层级递进与内容一致：主干、子流程、技术实现和补充说明出现在各自应有的层级上；子标题由独立逻辑关系产生，同一逻辑下的并列细节用列表或段落，没有为排版强行拆分。
4. 节首检验：每个主要章节开头交代了位置和产出。
5. 细节位置与表达形式：实现细节紧跟它所解释的步骤，没有集中堆放在章节末尾；正文形式（标题、列表、表格、引用块）与内容性质匹配，执行步骤、技术细节、约束条件和补充说明一眼可辨。
6. 折叠检验：抽查最复杂的两三处（默认值，可后改），遮住深入与边界内容后，主干仍完整、连贯、正确（定义见《讲解规范》的小节内部纪律）。
7. 复杂子流程有自己的骨架，结束后接回主线。
8. 会改变全篇结论的事实不只出现在补充块里。
9. 图：图例与实际图形一致；关系类型画法正确；另一次执行已标出；图、正文、小结对同一件事的描述一致。
10. 声明的数量与清单一致。

**流程与数据去向检查：** 沿流程六问正向走查，再从结果反向追关键数据；每个影响结果的数据有真实来源，每个分支有承接者和结果；同一次执行与不同次执行分清；覆盖本篇实际存在的跨请求、线程、事务、进程边界，以及容易混淆的对象。

组织检查靠阅读完成；`skeleton` 和 `lint` 只帮助定位。

## G4：事实与结论强度准确

正文事实能在理解稿里找到带源码位置的解释；意图型解释有出处。每个大步至少抽查一处关键断言（默认值，可后改），优先核对生成时机、实际接线、事务与失败范围、跨组件交接和重要数字。发现错误时，先修理解稿，再改正文，并扩大检查到共享同一前提的断言、图和追问答案。主文、图、小结对同一事实冲突时，不能各自通过。教学示例抽查两点：示例遵循已核实的规则；示意性质已标明。未知的范围如实保留，不把设计预期、协议示意或模拟行为写成已实现的能力。

## G5：正文承担讲解

运行 `lint` 取得候选，再人工判断；脚本没有命中不代表通过。下面后几类要通读。

| 信号 | 怎样判断和处理 |
|---|---|
| 路径加行号、测试类或方法名清单 | 移到理解稿；少数立即跳转有助理解的位置可以保留并记录理由 |
| “本次未运行”之类的核验过程说明、入口编号、来源编号 | 移到理解稿和 99 |
| 迁移号、版本号堆列 | 移到理解稿；确需讲版本演进时，讲旧做法、问题与变化原因 |
| 解释性标签合计超过约 5 处（默认值） | 检查能否改写成经核实的效果型解释，或把不影响理解的未知移到 99 |
| 连续约 4 句只写配置、数字、名称或条件（默认值） | 把事实组织成机制：补作用、原因和步骤，不只是删数字 |
| 机制只有名称和参数 | 补足问题、工作方式与失败行为 |
| 写了“见第 NN 篇”而本篇没有够用讲解 | 在使用处先补①③⑤，再指向主讲篇 |
| 某一节补充块多于主干，或补充块过密 | 检查主次是否倒置、主线是否被切碎 |
| 数量声明没有清单 | 补清单，或去掉数量声明 |

数值都是默认值，可后改。正文中属于业务概念的“证据”“冻结”“快照”等词不按关键词删除。

## G6：表达

在结构稳定的正文上，按《表达规范》逐节检查：过程是否说完整；术语是否在首次使用处解释；名称密度；因果是否具体；限定与否定的写法；句子是否过度压缩；有无模板转场和修改痕迹。记录实际问题与修改位置，以及保留候选的理由。结构问题归 G3，不在这一门处理。表达修改不改变事实和结论强度。“已运行风格检查 Skill”不能代替逐节检查。

## 问题分级与处理

| 问题 | 处理 |
|---|---|
| P0 错误事实或虚假保证 | 回源码，修理解稿和全部相关的正文、图、答案，复验；不通过不得交付 |
| P1 结构或理解缺口（复述不通过、主线错误、机制缺口） | 已有事实足够时，先更新讲述方案再重组；依据不足时退回研读；整体结构变化后重跑骨架复述 |
| P2 局部表达问题 | 原位改写，检查原义和受影响的追问 |
| 仅为个人措辞偏好 | 可以保留，不做无限润色 |

任何一道门不通过，都要指明是规则执行问题、理解缺口还是资料不足，并登记需要返工的单元；不用平均分或其他门的通过来抵消。

## 冲突取舍

| 冲突 | 取舍 |
|---|---|
| 深度与准确 | 不确定就回源码；确认不了就讲到已确认处，缺口记 99，不编造 |
| 理解与覆盖 | 次要分支可以简述或留在理解稿；核心机制的七问不能省 |
| 理解与精简 | 删重复、空话和无关的核验细节；保留背景、原理、过程和例子 |
| 主线与深入 | 改变位置、层级或篇目来安放深入内容，而不是删掉它 |
| 结构与表达 | 先把结构改对，再润色句子 |
| 示例与事实 | 以事实为准；示例调整或移除 |
| 单篇可读与跨篇重复 | 使用篇保留够用讲解，完整讲解由主讲篇承担 |
| 用户要求与固定规范 | 按用户要求执行，在变更记录里写明偏离了哪条规范 |
