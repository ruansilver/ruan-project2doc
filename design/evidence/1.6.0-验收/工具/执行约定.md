- 被测规则在 `D:/AI workspace/program/ruan-project2doc/src/ruan-project2doc/`：`SKILL.md`、`references/`（九份）、`templates/`（十四份）、`scripts/project2doc.py`。**按这些文件做**，不凭对旧版的印象；它们和 1.4、1.5 不同。

## 只读边界（违反即为测试事故）

- **只读**：被分析的源码仓（`D:/AI workspace/program/ruan resume/项目/…`）、用户的笔记工程（`D:/AI workspace/claimYourPro/…`）、本仓库的 `design/`、`install/`、`src/ruan-project2doc/`、`src/tests/`。
- 在源码仓和用户笔记工程里**不运行任何写入命令**：不构建、不跑测试、不 `git checkout/stash/pull/clean`、不改文件；只允许读文件与 `git log/show/rev-parse/status/diff` 这类只读命令。
- **只在任务书指定的测试工程目录（`src/.work/1.6-验收/T…/` 下）写文件**。测试工程内的旧笔记线索、夹具都只读；写修订版时写新文件。
- 不 `git add`、不 `git commit`、不 `git push`。
- Windows 环境：路径加引号；Python 一律 `python -X utf8`。

## 工作方式

- 如实记录：没执行的检查不写成执行过；没核实的事实标注“待核实”，不编造。脚本通过不代表质量通过。
- 每个事实要有源码位置（文件路径 + 能指到位置的描述）；引用旧笔记线索时，写进产出的每个事实都要回当前源码核实。
- 产出写到任务书指定的路径，编码 UTF-8，换行 `\n`。
- 最后回报：产出文件清单、关键数字（行数、章节数等）、没能核实或没执行的项、下一步建议。回报要短。

## 独立读者的额外约束

承担独立读者时：你**只**阅读任务书给出的那一个输入文件；不读取其他任何文件、不搜索目录、不使用外部知识补答案。正文没讲清的地方如实标出“判断不了/没讲清”。每个阶段的回答先写入指定的答案文件，写完再回报。
